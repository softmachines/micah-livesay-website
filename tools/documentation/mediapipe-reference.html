GESTURE RECOGNITION

The GestureRecognizer model returns one of the following named gesture labels per detected hand, along with a confidence score (0.0–1.0) and the full 21 hand landmarks. It can detect up to 2 hands simultaneously.

CDN import:
import { GestureRecognizer, FilesetResolver } from 'https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.3'
Label string Description Reliable range Notes
Closed_Fist All four fingers curled into palm, thumb tucked or alongside 0.85 – 1.0 Most reliable gesture. Loose fists (e.g. holding something) may score lower.
Open_Palm All five digits fully extended and spread, palm facing camera 0.80 – 1.0 Requires relatively frontal palm orientation. Side-on hands score lower.
Pointing_Up Index finger extended upward, remaining fingers curled 0.75 – 1.0 Confused with "Victory" if middle finger partially extends. Angle-sensitive.
Thumb_Up Thumb extended upward, remaining fingers curled into fist 0.80 – 1.0 Also detects horizontal thumbs up. Thumb pointing down ≠ Thumb_Down without rotation.
Thumb_Down Thumb pointing downward, remaining fingers curled 0.70 – 1.0 Less reliable than Thumb_Up. Requires clear downward orientation.
Victory Index and middle fingers extended in a V, others curled. The peace sign. 0.80 – 1.0 Works palm-facing or back-of-hand. Finger spread angle doesn't matter much.
ILoveYou Index finger, pinky, and thumb extended. Rock/metal horns with thumb out. 0.75 – 1.0 Thumb must be clearly extended to distinguish from standard horns gesture.
None No gesture classified — hand detected but no match found — Returned when hand is visible but gesture confidence falls below threshold.
Important: These are the only 7 named gestures the built-in model recognises. You cannot detect arbitrary gestures (e.g. "OK sign", "crossed fingers") without training a custom classification layer on top of the hand landmarks. The alternative — computing gesture from landmark geometry directly — is covered in the theremin codebase (handOpenness()).

Confidence thresholds in practice

The model returns gestures[handIndex][0].score. A threshold of 0.7 works well as a trigger point — below that, treat as "None". For held states (e.g. "hold fist for 1s"), smooth the score with an exponential moving average to avoid flickering.

const result = gestureRecognizer.recognizeForVideo(videoEl, performance.now());
const gesture = result.gestures[0]?.[0];  // first hand, top result

if (gesture && gesture.score > 0.75) {
    console.log(gesture.categoryName); // e.g. "Closed_Fist"
}

FACE STYLIZER — ARTWORK BRIEF

The FaceStylizer model takes a source image and applies an artistic style to the detected face region in real time. The style image is baked into the model at training time — you don't pass a live style image at runtime. This means a graphic artist creates the artwork once, a developer uses it to build a custom .tflite model, and that model is then loaded in place of the default.

Key constraint: You are not applying a texture or overlay — you are training a neural style transfer model from your artwork. The model learns the overall visual language (colour palette, stroke style, texture) of the reference image and applies it to new face geometry.

How the pipeline works

1 — ARTWORK

Artist creates the reference style image. This defines the aesthetic the model will learn.

2 — MODEL TRAINING

Google's Model Maker (Python) trains a new .tflite model using the artwork as the style target. Takes ~hours on GPU.

3 — BROWSER DEPLOY

The .tflite file is loaded via baseOptions.modelAssetPath exactly like the hand model.

What makes a good style reference image

ConsiderationRecommendationWhy
Resolution256×256 px minimum, 512×512 px idealThe model downscales internally. Higher res captures more detail but training takes longer.
Content vs styleAbstract / textural imagery works better than figurative artA portrait of a face trains the model to apply face-specific features, not the style. Use texture, colour field, brushwork.
Colour paletteHigh contrast, distinct huesSubtle colour shifts get lost in quantisation. Bold neons, deep blacks, and high saturation transfer well.
Edge characterDefined stroke edges and clear texture directionalityThe model picks up stroke direction and edge sharpness. Soft watercolour blends produce muddy results on faces.
Luminance variationInclude a full tonal range (darks, mids, lights)If your image is all dark or all light, face shadows and highlights get crushed.
Aspect ratioSquare (1:1)The model operates on square crops of the face region.
File formatPNG or high-quality JPGCompression artefacts (especially JPEG blocks) can be learned as texture unintentionally.
BackgroundSolid or minimal backgroundBackground texture will leak into the model. Use a flat black or white.

Styles that transfer well to faces

CIRCUIT / TECH

Printed circuit board traces, glowing wire paths, geometric node patterns. High contrast. Works well for the cyberpunk aesthetic of this project.

INK / WOODBLOCK

Strong black outlines, flat colour fills, defined hatching direction. Japanese woodblock prints and linocut style both train reliably.

GLITCH / SCAN

Horizontal scan-line patterns, chromatic shift textures, CRT phosphor patterns. The directional noise trains well and maps naturally to face planes.

OIL / IMPASTO

Heavy directional brushwork with visible stroke direction. Works well if strokes are large relative to image size.

MOSAIC / PIXEL

Large pixel grid, stained glass, or chunky geometric tiles. The model learns the grid structure well.

NEON / GLOW

Glowing outlines on black. Works if the glow is defined by texture/gradient rather than just a CSS blur. Paint it, don't filter it.

Styles to avoid or test carefully

Style typeProblem
PhotorealismThe model learns to reproduce the photograph rather than a style — output looks like a blended face.
Watercolour / soft gradientsBlends merge into muddy skin tones. Low-frequency colour fields need strong underlying texture to anchor the transfer.
Very dark imagesFace highlights get crushed. The model maps its tones to the face — if your reference has no lights, neither will the output.
Text / typographyCharacters appear distorted across curved face geometry. Avoid unless intentional as a texture element.
Single flat colourNo style information for the model to learn. Adds a colour tint but no visual character.

For a graphic artist — the brief in plain language

What to create: A square image (512×512 px, PNG) that communicates a visual style through texture, colour, and mark-making rather than through subject matter. Think of it like a fabric swatch or a wallpaper tile — it should tile visually in the mind, even if it doesn't literally tile. The AI will learn to paint faces in the visual language of your image.

What to avoid: Faces, portraits, or recognisable objects. The AI needs to learn how the surface looks, not what it depicts.

Deliver: The style reference image itself (PNG, 512×512) plus ideally 3–5 variations at different contrast levels so the developer can test which trains most effectively.

Training with Google Model Maker (developer reference)

# Python — requires mediapipe-model-maker
from mediapipe_model_maker import face_stylizer

# Point at your style image
spec = face_stylizer.StylizerSpec(
    style_image='path/to/your_style_reference.png'
)

# Train — takes 30–120 minutes depending on GPU
model = face_stylizer.FaceStylizer.create(spec)
model.export_model('my_style.tflite')

INTEGRATION PATTERNS

Combining multiple models

Each model runs its own inference call. For the theremin or webcam, you can chain them in the same requestAnimationFrame loop — hand landmarks first (cheap), face landmarks second (slightly heavier). Keep the video element shared.

// Run both in the same rAF loop
function renderLoop(ts) {
    requestAnimationFrame(renderLoop);

    // Hand tracking — already in use
    handResults = handLandmarker.detectForVideo(videoEl, ts);

    // Face tracking — add this
    faceResults = faceLandmarker.detectForVideo(videoEl, ts);
    const bs = faceResults.faceBlendshapes[0]?.categories;

    // Map to audio / visuals
    if (bs) {
        const jawOpen = bs.find(b => b.categoryName === 'jawOpen')?.score ?? 0;
        // e.g. filter.frequency → map jawOpen to cutoff
    }
}

Smoothing — exponential moving average

Raw blendshape values flicker frame-to-frame. Smooth before mapping to audio parameters:

let smoothJaw = 0;

// In render loop:
smoothJaw = smoothJaw * 0.8 + rawJawOpen * 0.2;
// 0.8/0.2 = slow smooth · 0.5/0.5 = fast response
filter.frequency.setTargetAtTime(
    mapToFreq(smoothJaw),
    audioCtx.currentTime,
    0.05  // additional smoothing from Web Audio
);
